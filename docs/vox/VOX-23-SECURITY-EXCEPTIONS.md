# VOX-23 Security exception: evidence, controls and owner decision

**Date:** 14 October 2026. **State:** OPEN — risk acceptance NOT granted. This is **source-only/read-only verification, not a remediation** and not permission to apply seven pending VOX migrations.

## Source audit and actual managed Staging read-only catalogue
- The existing `public.vendor_public_v` is an intentionally owner-rights (not `security_invoker`) **21-column projection**, with an exact `Approved AND active AND public_visibility AND remaining_credits > 0` predicate. Anonymous `SELECT` on `public.vendors` is DENIED, anonymous SELECT on the public view is allowed, and anonymous UPDATE denied. Because the listing view owner can read the underlying table despite anonymous base SELECT denial, enabling `security_invoker=true` **would break public listings**, or require a separately reviewed redesign of column-level table privileges and Data API exposure.
- The `public.is_admin()` and `public.owns_vendor(uuid)` functions are `SECURITY DEFINER` helpers used by existing authenticated RLS policies, with `auth.uid()` and schema-qualified `public.profiles`/`public.vendors` access, `search_path=public`. Real catalogue verified anon EXECUTE denied on both, authenticated EXECUTE allowed as policy requires, and **neither anon nor authenticated may CREATE in the public schema**.
- Current Supabase advisories remain open: one SECDEF view ERROR, two authenticated callable SECDEF helper WARN, leaked-password protection disabled WARN, 102 RLS-with-no-policy INFO. Those labels are **not** a substitute for exploit proof or owner waiver. The disabled leaked-password protection is a genuine external Supabase Auth platform setting requiring privileged dashboard access; do not claim resolved.
- The view design appears compatible with the existing public listing and restrictive raw privileges, but a risk owner must separately review view owner privileges, object dependency drift, all public contact/URLs, RLS policy intent and authenticated SELECT semantics. Do not assert the design has zero risk merely because safe columns were found.

## New automated checks
- `validate-vox23-security-exceptions.mjs` fails closed if the historical public 21-column view allowlist or exact visibility predicate changes, base/public grants drift, RLS helper identity logic changes, or evidence claims owner acceptance.
- Includes five negative tests for a new private column, public row-filter OR, Pending instead of Approved, removed view grants, and removed authenticated identity check.
- `ops/vox/staging-security-readonly.sql` is **SELECT ONLY**, returns boolean catalogue evidence without any live vendor rows or PII. It must be executed in actual managed Staging and reconciled with the source snapshot before signed promotion; it cannot enable a feature or alter permissions.
- This check certifies baseline **guardrails** and flags residual risk; it does not eliminate Supabase's SECDEF warnings or the need for privileged Auth leaked-password protection enablement.
