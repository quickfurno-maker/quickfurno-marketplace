## Real observed baseline, with decision

- `public.vendor_public_v` intentionally acts as privileged *read-only public projection* of `public.vendors`, exposing precisely **21 public columns**, filtered to approved, active, publicly visible vendors with positive credits. Anonymous users may SELECT the view but **may neither SELECT `public.vendors` nor UPDATE the view**. This is why a simple `security_invoker=true` toggle would break public discovery. **One Supabase Advisor ERROR remains an explicitly-reviewed architectural exception, NOT remediated.** A redesign into a separately maintained public safe table or narrowly qualified data-access architecture would require E2E product compatibility, RLS and privacy review.
- `public.is_admin()` and `public.owns_vendor(uuid)` remain `SECURITY DEFINER` and authenticated-EXECUTE because they support existing RLS. Anonymous-EXECUTE is revoked. Their SQL bodies reference `public.profiles`, `public.vendors`, and `auth.uid()` explicitly. No anonymous or authenticated roles have `CREATE` on schema `public`. Both advisor WARNs are **open reviewed exceptions**, not grounds for indiscriminate REVOKE that would break vendor authorization. Optionally tighten function search paths to empty in a separately authorized migration **after** proving full SQL/RLS compatibility.
- Exactly **102 tables with enabled RLS and no policies** currently have **zero anon SELECT grants and zero authenticated SELECT grants**. This is an intended fail-closed server-only posture, subject to future audit of service-role usage. Do not create permissive policies merely to hide linter INFO.
- **Supabase Auth leaked-password protection is currently DISABLED**. This is an **unresolved platform configuration issue**, not fixable from the SQL release source. Authorized operator must enable it via Auth Settings after checking plan/provider, then recheck Auth advisor and actual login behavior. Never claim full security closure until this passes.

## Release gate

The new source gate prevents accidental exposure of new private vendor columns, anonymous base privileges, writable view, missing approved-only filters, anonymous privileged RPC execution, public schema CREATE grants, or anon/authenticated SELECT on no-policy tables. It fails closed on project mismatch or migration drift. All checks return `allowManagedStageMigration=false` and `allowProductionCutover=false`, even on the expected baseline, since real backup/restore, current production/JWT tests and outstanding Auth config still block release.

**No managed Staging or Production changes were made.** On the live managed database, genuine backup+isolated restore still pending, **86 historical migrations/0 VOX**, and Core/Jarvis/AGNI aggregates remain draft/unmerged.
