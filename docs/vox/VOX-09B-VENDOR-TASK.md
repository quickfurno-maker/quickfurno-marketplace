# VOX-09B — Native Vendor CRM task creation, role+vendor+city bounded

**SOURCE ONLY; NOT DEPLOYED; FLAG OFF.** Adds a narrow `POST /api/vox/v1/vendor-task` using existing QuickFurno `services/vendorCrmService.createVendorTask`, not another CRM engine or a raw table write. A newly verified AAL2 Core staff actor must have an active `vendor_success_agent` or `operations_manager` role, an exact unexpired vendor grant, and the canonical vendor's active service zone must still match the actor's assigned Core city. Input is whitelisted to bounded task type, title, priority, future due date and client UUID nonce. Audit actor is always derived from the signed Core Auth context. The Vendor CRM already supports idempotency keys; the VOX adapter hashes **actor + vendor + nonce** to avoid ID collisions or leaks across vendors.

Task creation only adds a **native internal staff CRM task**; it does not update vendor verification, KYC/Aadhaar, profile, credits, leads, consent, WhatsApp or Jarvis. Urgent/privileged task types are deliberately rejected. Unknown actions and other HTTP methods fail closed. Default OFF `VOX_VENDOR_CRM_TASKS_ENABLED`. A full two-person approval for *every* routine CRM follow-up is not currently part of the canonical task service and should be explicitly decided before real enablement. No live Staging data or credential used.

**Open gate:** real verified Auth AAL2, PostgREST city and object scope HTTP E2E, idempotency concurrency, native CRM DB transaction/outbox and operator audit, Origin/rate protection, Staging-backed rollout. Source unit checks cannot certify live authorization or privileged provider behavior.
