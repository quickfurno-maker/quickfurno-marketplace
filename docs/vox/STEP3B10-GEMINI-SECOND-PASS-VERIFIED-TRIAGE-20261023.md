## Important Gemini claims corrected or qualified
1. **Blanket direct-table RLS writes overstated.** 23 Oct live SELECT-only Staging `has_table_privilege('authenticated',...,'UPDATE')` returns **false** for `public.profiles` and `public.vendors`, including columns `role`, `is_active`, `status`. Other actor/role/view/function grants still require testing. Conditional unauthorized reads are a real risk: `authenticated` has SELECT on profiles/vendors and `is_admin()` lacks active check. This supports P0 AppSec review, but not Gemini's claim that an inactive Admin can mutate every protected table.
2. **Affected table privilege inventory:** of 69 helper-dependent policies across 40 public tables, 16 apply to tables with `authenticated` SELECT privilege, 2 to a table with direct write grant (both `public.audit_logs` policies). Audit logs have `audit admin insert` WITH CHECK `is_admin()` and `audit admin read` USING `is_admin()`, requiring immediate effective tests; mere table UPDATE/DELETE grants are not proof RLS allows those commands. Other tables may be reachable through SECURITY DEFINER/server-side routes, so no all-clear.
3. **Backup scope misdescribed in Gemini report.** The dated Staging `pg_dump` script explicitly includes `--schema=public --schema=auth --schema=storage --schema=supabase_migrations` with `--no-owner --no-acl`. It is incorrect to claim Auth and Storage metadata are categorically omitted; **global roles/ACL, physical object-storage files, PITR and full restore certification ARE missing**. Restoring Auth metadata may have session/device consequences; no production rollback certified.
4. **CI 'no Web tests' overstated.** The Finance-specific workflow `.github/workflows/finance-v2-pay3-hold.yml` previously ran Web typecheck+build without `npm test`; however `.github/workflows/vox-source-gates.yml` and `vox-integrated-candidate.yml` DO run `apps/vox-web npm test`. Added `npm test` to Finance-specific VOX Web job as defense-in-depth. Source tests do not replace real Staging.
5. **VM-module SIGSEGV cause unverified.** The EOD spec uses actual `vm.SourceTextModule` and `vm.SyntheticModule`, for which `--experimental-vm-modules` is intentionally used. It is unsafe to remove this flag casually; isolate/diagnose Linux runner, versions and memory before changing harness. No source assertion failure was established on first run.
6. **`adminClient()` is intentional privileged API composition, not independently proof of API bypass.** `app/api/vox/v1/overview/route.ts` first calls `verifyVoxOwnerBearer()` and returns 401 when absent, then runs restricted reads via `adminClient()`. It deliberately bypasses RLS at DB layer; complete safety depends on the verifier and every route. Independently review Owner/AAL2 auth, signatures, least privilege and response scope, but do not call presence of `service_role` alone confirmed exploit.
